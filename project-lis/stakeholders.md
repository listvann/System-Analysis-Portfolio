# Реестр стейкхолдеров и анализ требований (ЛИС)

В данном документе представлен реестр заинтересованных лиц для обновленной версии лабораторной информационной системы, а также их классификация по матрице влияния Менделоу.

## 1. Реестр стейкхолдеров

| Группа | Роль | Зона ответственности и боли | Ожидания от системы |
| :--- | :--- | :--- | :--- |
| **Внутренние** | **Заведующий лабораторией** | Контроль сроков выдачи (TAT), расход реагентов, процент брака. | Дашборды с аналитикой, прозрачность загрузки анализаторов. |
| **Внутренние** | **Фельдшер-лаборант** | Валидация результатов, постановка биоматериала в анализаторы. Боль: ручной ввод данных. | Автоматическая маршрутизация по штрихкоду, автовыгрузка результатов с приборов. |
| **Внутренние** | **Процедурная медсестра** | Забор биоматериала, маркировка. Боль: путаница в цветах пробирок. | Понятная генерация штрихкодов, подсказки по типу пробирок в интерфейсе. |
| **Внешние** | **Пациент** | Сдача анализов, ожидание результатов. Боль: задержки и утечка данных. | Быстрое получение PDF-бланка на почту, защита персональных данных. |
| **Внешние** | **Минздрав / ЕМИАС** | Санитарно-эпидемиологический контроль (например, учет COVID-19). | Надежная интеграция (SOAP/XML) для передачи данных о выявленных инфекциях. |
| **Технические**| **IT-отдел / Сисадмин** | Поддержка серверов и БД. Боль: падение системы из-за пиковых нагрузок. | Отказоустойчивость, логирование ошибок, мониторинг (Zabbix/Grafana). |

## 2. Матрица «Власть / Интерес»

Для выбора стратегии коммуникации стейкхолдеры распределены по 4 квадрантам:

*   **Плотное управление (Высокая власть, Высокий интерес):**
    *   *Заведующий лабораторией:* Принимает решения о бюджете и успешности внедрения ЛИС. Требует регулярных демо-показов и согласования архитектуры.
    *   *Минздрав:* Диктует жесткие законодательные требования к форматам обмена данными (интеграционные контракты).
*   **Держать удовлетворенными (Высокая власть, Низкий интерес):**
    *   *IT-отдел:* Не пользуются ЛИС напрямую, но могут заблокировать релиз, если архитектура не соответствует стандартам безопасности клиники.
*   **Держать в курсе (Низкая власть, Высокий интерес):**
    *   *Фельдшер-лаборант и Медсестра:* Главные пользователи. Их власть ограничена, но от их удобства (UX) зависит скорость работы лаборатории. Необходимо собирать обратную связь на этапах тестирования.
*   **Минимальное усилие / Мониторинг (Низкая власть, Низкий интерес):**
    *   *Пациент:* Взаимодействует только с финальным артефактом (бланком результата). Коммуникация идет в одностороннем порядке (нотификации).
