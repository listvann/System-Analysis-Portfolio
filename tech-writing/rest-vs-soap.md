# Шпаргалка: REST vs SOAP (с примером на ЛИС)

Краткая памятка по базовым подходам к проектированию API. В чем разница форматов и что лучше выбрать для интеграции медицинских систем.

---

## 1. SOAP (Simple Object Access Protocol)
Это строгий протокол обмена сообщениями. Работает по жестким правилам: структура запроса и ответа строго регламентирована.

*   **Формат:** Только XML.
*   **Транспорт:** Чаще всего HTTP/HTTPS, но поддерживает SMTP, TCP.
*   **Контракт:** Описывается через WSDL (жесткая схема, шаг влево-вправо — ошибка).
*   **Плюс:** Максимальная надежность и встроенная криптография (WS-Security). 

**Как выглядит конверт (запрос данных пациента):**

    <soapenv:Envelope xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/">
       <soapenv:Header/>
       <soapenv:Body>
          <getPatientInfo>
             <patientId>12345</patientId>
          </getPatientInfo>
       </soapenv:Body>
    </soapenv:Envelope>


## 2. REST (Representational State Transfer)
Это архитектурный стиль, а не протокол. Он гибче, легче и использует стандартные механизмы самого веба (HTTP).

*   **Формат:** Практически любой. Обычно используют JSON, так как он легче читается.
*   **Транспорт:** Только HTTP/HTTPS.
*   **Контракт:** Гибкий (обычно описывается в Swagger / OpenAPI).
*   **Плюс:** Высокая скорость, простота парсинга на фронтенде. Использует понятные методы (GET — получить, POST — создать, PUT/PATCH — обновить).

**Как выглядит запрос (получение данных пациента):**

    // GET /api/v1/patients/12345
    
    {
      "id": 12345,
      "name": "Иван Иванов",
      "status": "active"
    }

## 3. Практика: Как выбрать формат для ПЦР-лаборатории

Часто в рамках одной Лабораторной информационной системы (ЛИС) приходится использовать оба подхода. Разберем на примере процесса «Выдача результатов анализов».

**Кейс 1: Мобильное приложение для пациентов (Выбираем REST)**
Пациенту нужно посмотреть результат ПЦР-теста со смартфона. 
Мобильному клиенту критически важна скорость и экономия трафика. Нам не нужны тяжелые XML-конверты. Мобилка дергает API через обычный `GET`-запрос и мгновенно получает легкий JSON-файл с результатом и референсными значениями.

**Кейс 2: Интеграция ЛИС с ЕМИАС или Минздравом (Выбираем SOAP)**
Лаборатория обязана выгружать результаты инфекционных тестов в гос. реестр. 
Госшлюзы требуют гарантии доставки и строжайшей безопасности. Потеря пакета недопустима. Здесь идеален SOAP с его строгой валидацией по WSDL-контракту и встроенным шифрованием, несмотря на то, что парсить XML сложнее и дольше.

## Краткий итог
Нужна скорость, легкость и работа с веб/мобайл фронтендом — берем **REST + JSON**. 
Нужны железобетонные транзакции, интеграция с неповоротливым Enterprise или госструктурами — берем **SOAP + XML**.
